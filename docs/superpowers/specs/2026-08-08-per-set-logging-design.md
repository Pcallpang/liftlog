# 세트별 무게 기록 · 커스텀 종목 삭제 설계

작성일: 2026-08-08

## 배경

미요 트레이너 사용 피드백 두 가지.

1. 세트마다 무게가 달라질 수 있는데(드롭세트, 워밍업 세트) 현재는 기록 1건에 무게와
   목표 반복수가 하나뿐이다. 세트별로 무게·목표 횟수·실제 횟수를 따로 넣고 싶다.
2. "직접 입력"으로 추가한 종목이 칩으로 남는 건 좋지만, 오타로 잘못 넣으면 지울 방법이
   전혀 없다.

## 1. 데이터 모델

현재 기록 1건:

```js
{ id, date, exercise, type: "strength", weight: 60, targetReps: 10, sets: [10, 8, 9] }
```

변경 후 — 세트가 숫자 배열에서 객체 배열로 바뀌고, 최상위 `weight` / `targetReps`가 사라진다:

```js
// 웨이트
{ id, date, exercise, type: "strength",
  sets: [ { weight: 60, targetReps: 10, reps: 10 },
          { weight: 60, targetReps: 10, reps: 8 },
          { weight: 50, targetReps: 10, reps: 9 } ] }

// 맨몸 횟수 운동 (풀업 등) — 무게 없음
{ id, date, exercise, type: "reps_or_duration", mode: "reps",
  sets: [ { targetReps: 10, reps: 10 }, { targetReps: 10, reps: 8 } ] }
```

`distance_time`과 `reps_or_duration` + `mode: "duration"` 기록은 세트가 없으므로 그대로다.

### 마이그레이션

`loadHistory()`에서 읽을 때 `sets` 원소가 숫자면 각 세트가 기록의 옛 `weight` /
`targetReps`를 물려받는 객체로 펼친다. 한 건이라도 바뀌면 즉시 재저장해 한 번만 변환한다.

`sanitizeHistoryEntry()`는 **두 모양 모두** 받아 새 모양으로 정규화한다. 이 변경 전에
내보낸 백업 파일을 나중에 가져와도 정상 복원돼야 한다.

이 작업에서 유일하게 되돌리기 어려운 부분이라, 적용 전 백업 내보내기를 권한다.

## 2. 입력 화면

상단 `무게 (kg)` / `목표 반복수` 칸은 남기되 **기본값** 역할로 바꾼다
(라벨: `기본 무게 (kg)`, `기본 목표 횟수 (세트당)`). 무게와 목표는 한 번만 적으면 모든
세트에 깔리고, 달라진 세트만 탭해서 고친다.

실제 횟수는 성격상 세트마다 다르므로 기본값으로 채우지 않는다. 하지 않은 횟수를 미리
채워두면 달성하지 못한 기록이 저장될 수 있어서다. 따라서 세트 행은 실제 횟수가 아직
없어도 물려받은 무게·목표를 보여준다 (`60kg · 목표 10회 · 횟수 입력`). 기본값 칸이
먹히지 않은 것처럼 보이지 않게 하려는 것이다. 세트 수만큼 모달을 여는 대신
`저장 후 다음 세트 →`로 한 번 열어 끝까지 넘긴다.

```
기본 무게        [ 60 ] kg
기본 목표 횟수   [ 10 ] 회

세트별 기록
┌──────────────────────────────┐
│ 세트 1   60kg · 10/10회   × │ ← 탭하면 모달
│ 세트 2   60kg ·  8/10회   × │
│ 세트 3   50kg ·  9/10회   × │  (목표 미달 세트는 강조)
└──────────────────────────────┘
        [+ 세트 추가]
```

### 기본값 vs 세트별 값

세트는 메모리 배열 `logSets`로 들고, 각 세트의 `weight` / `targetReps`는 **숫자 또는
`null`** 이다. `null`은 "기본값을 따른다"는 뜻이고, 표시·저장 시점에 상단 기본값 칸에서
해석한다.

- `+ 세트 추가`는 `{ weight: null, targetReps: null, reps: null }`을 넣는다 → 기본값 추종
- 모달 저장 시 입력값이 현재 기본값과 **같으면 `null`로 두고, 다르면 숫자로 고정**한다

이 규칙 덕분에 기본 무게를 60 → 65로 고치면 따로 안 만진 세트는 따라 움직이고, 50kg으로
직접 지정한 드롭세트는 그대로 남는다. 숨은 플래그 없이 값만 보고 판단한다.

### 세트 모달

`세트 N` 행을 탭하면 뜬다. 칸은 `무게`(웨이트 운동만) / `목표 횟수` / `실제 횟수` 3개,
현재 해석된 값이 미리 채워진다. 버튼은 `취소` · `저장` · `저장 후 다음 세트 →`
(마지막 세트가 아닐 때만). 마지막 버튼이 있어 3세트를 모달 한 번 열어 끝까지 넘길 수 있다.

- 열면 첫 칸에 포커스
- ESC 키, 배경 탭 → 취소
- `저장 후 다음 세트`는 `type="button"` + `reportValidity()`로 검증한다.
  `submitter` / `requestSubmit`은 구형 iOS Safari 지원이 불확실해 쓰지 않는다.
- 기존 `profile-modal` / `settings-modal`과 같은 `modal-overlay` + `modal-card` 구조를 따른다

## 3. 기록 카드 표시

세트별로 값이 다를 수 있으니 표시를 바꾼다.

- 배지 (웨이트): 무게가 전부 같으면 `60kg`, 다르면 `50~60kg`
- 배지 (맨몸 횟수): 목표가 같으면 `10회 목표`, 다르면 `8~10회 목표`
- 세트 칩: `세트 1: 60kg · 10/10회` — 미달 판정은 **그 세트 자신의 목표** 기준
- 성공 여부(`isEntrySuccess`): 모든 세트가 각자 목표를 채웠는지
- 메타: 목표가 전부 같을 때만 `목표 10회 · 3세트`, 다르면 `3세트`

## 4. AI 프롬프트 (server.py)

세트별 값을 그대로 넘긴다:

```
- 2026-08-08 벤치프레스 3세트(60kg 10/10회, 60kg 8/10회, 50kg 9/10회) [일부 실패]
```

서버는 클라이언트가 보낸 히스토리를 그대로 읽으므로, 캐시된 구버전 클라이언트가 옛 모양을
보낼 수 있다. 숫자 세트와 객체 세트를 모두 받아 처리한다.

## 5. 커스텀 종목 삭제

- 저장 계층에 `removeCustomExercise(part, exercise)` 추가. 목록이 비면 부위 키도 지운다.
- 직접 추가한 칩에만 `×`를 상시 표시한다. 기본 제공 종목엔 붙지 않는다.
- 칩 안에 버튼을 중첩하면 잘못된 HTML이라, `칩 버튼 + × 버튼` 한 쌍을 감싸 알약 모양으로
  스타일링한다.
- `×` 탭 → 확인창 → 삭제 → 칩과 숨은 `<select>` 둘 다 갱신
- 지운 종목이 선택 중이었으면 첫 종목으로 되돌린다
- **과거 기록은 손대지 않는다.** 기록은 종목명을 문자열로 갖고 있어 목록에서 빠져도 그대로
  남고, 수정 화면에서는 기존 "부위를 못 찾음" 경로가 직접 입력 칸으로 받아준다.

확인창은 앱 전용 모달을 새로 만들지 않고 브라우저 `confirm()`을 쓴다. 전체 초기화 등
기존 파괴적 동작이 이미 `confirm()`을 쓰고 있어 그쪽에 맞춘다.

## 6. 검증

저장소에 테스트 러너가 없어 브라우저에서 직접 확인한다.

1. 기존(마이그레이션 전) 기록이 변환 후 값 그대로 보이는지
2. 세트별 무게가 다른 새 기록 저장 → 카드 배지가 범위로, 칩이 세트별 값으로
3. 기본 무게를 고쳤을 때 미지정 세트만 따라 움직이는지
4. 이 변경 전 내보낸 백업 파일 가져오기
5. 기록 수정 진입 → 세트 값이 그대로 복원되는지
6. 커스텀 종목 삭제 후 그 종목을 쓴 과거 기록이 남아 있는지

## 7. 서비스 워커 캐시
